# Doc standard

Everything under `docs/` is written for an AI agent, not for a human reading
cover to cover. An agent arrives with a task, needs the map and the traps, then
reads the actual code. Optimise for that: maximum facts per token, no tutorials.
A human who wants an explanation asks an agent for one.

## Rules

1. English. Terse. No motivation paragraphs, no narrative history, no
   restating what the previous sentence said.
2. A doc is an index and a memory, not a copy of the code. Never paste a config
   or script the agent can read in one call - point at it. Quote only the exact
   fragment a claim hinges on, at most a few lines.
3. Keep what cannot be re-derived from the repo: why a thing is shaped this
   way, what was tried and failed, upstream bug links and dates, the commands
   that prove it works, ordering constraints, invariants that break silently.
4. Assume standard technology is known. `systemd`, `nftables`, `netns`,
   `socat`, `podman`, `chezmoi` templates need no introduction. Explain only
   what is specific to this repo.
5. Anchor every non-obvious claim to `path/to/file` plus a function name,
   heading or unique string. Never a bare line number (CLAUDE.md rule 6).
6. Size: 1.5-8 KB per doc. Past that it either covers two topics (split it and
   update `README.md`) or explains where it should state.
7. Mermaid only when a diagram replaces more prose than it costs: at most one
   per doc, at most ten nodes. Default is no diagram.
8. No live command transcripts. A measurement worth keeping becomes one line
   with its date: `zen RSS ~2.4 GB with 40 tabs (measured 2026-07-30)`.

## Skeleton

These H2 headings, in this order. Drop any section that would be empty. Do not
invent other H2s - other docs link to these anchors, and `tools/gen-catalog.sh`
fails on a link to an anchor that does not exist.

| Heading | Contents |
|---|---|
| `## What it does` | 1-3 sentences: purpose, scope (host / container / both), feature key. |
| `## Files` | Table `Path \| Role`. Every pattern from `covers.paths` appears here; runtime paths the repo generates (units, `/etc` files) belong here too, marked as such. |
| `## How it works` | The mechanism, in bullets. H3 subsections allowed. |
| `## Constraints` | Invariants that break silently, ordering rules, permissions, each with its reason on the same line. |
| `## Decisions` | Table `Decision \| Why \| Rejected`. Only non-obvious ones. |
| `## Verify` | One `sh` block: commands plus the expected result as a comment. |
| `## Failure modes` | Table `Symptom \| Cause \| Fix`. |
| `## See also` | Links to other docs, `workarounds.md` rows, `issues/`. |

Frontmatter is copied verbatim when editing an existing doc. Its format is
parsed strictly (`tools/gen-catalog.sh`, `parse_header`): `covers:`, then
`  features: [a, b]` inline and either `  paths: []` or `  paths:` followed by
`    - pattern` lines. Anything else is a hard error.

## Linking

- A cross-doc link points at a file (`[containers.md](containers.md)`) or at
  one of the eight standard anchors above (`[verify](operations.md#verify)`).
  Never at an H3 in another doc.
- Links into `issues/` carry no anchor.
- `glossary.md` is linked as a whole file, never by anchor.
- Every link is checked, including anchors. Run `tools/gen-catalog.sh --check`
  after editing docs.

## Docs with their own shape

Six documents do not use the skeleton, because their job is not describing a
subsystem - the five below, plus this one.

- `README.md` - the map: one line per doc, grouped. No prose beyond the group
  headings.
- `catalog.md` - generated by `tools/gen-catalog.sh`. Never edited by hand.
- `glossary.md` - flat table of terms that are specific to this repo. Standard
  technology does not belong here.
- `workarounds.md` - registry of other people's bugs this repo works around.
  One row per workaround; every row keeps its evidence state and the check that
  tells whether the bug is still alive.
- `operations.md` - runbook: manual steps and diagnosis, command-first.

`issues/*.md` are investigation logs, one file per investigation, no
frontmatter, ~1 KB, fixed shape:

```markdown
# Title

Date. Status: fixed | open | wontfix.

**Symptom** what was observed.
**Root cause** what it actually was, anchored to a file or upstream issue.
**Fix** what changed in this repo, or why nothing changed.
**Recheck** the command that says whether it is still true.
```
